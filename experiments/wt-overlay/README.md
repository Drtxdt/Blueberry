# Windows Terminal 原生覆盖快照可行性原型

固定 Terminal `v1.24.12741.0` / `7ff11ee107c984e236960ec948b450ccbc10187b`。
用户于 2026-10-14 授权独立最小补丁／接口调查。该原型不安装 Terminal，
不修改用户设置，不提交微软仓库 PR，也不作为 Blueberry 发版通过证据。

第一阶段直接使用 Terminal 的 `TextBuffer`、`ROW`、`TextAttribute` 和原生
`Reflow`，不以 CHAR_INFO、UIA 或自行模拟的行模型代替。快照按原始宽度保存
覆盖行，保留原生属性对象、字形、宽字符边界、换行、图像行复制、双字节填充
及滚动标记。恢复必须在持有 Terminal 写锁且 **原生缩放前** 执行。

独立 CI 编译原生测试项目，测试 RGB／默认／索引颜色、独立下划线颜色及样式、
隐藏／保护等属性、中文／emoji／组合字符、URI、连续宽度变化，以及覆盖区域外
新增输入与链接。乱代次和 URI ID 冲突必须在写回前拒绝。

当前状态：原生编译成功，本机 SDK TAEF 明确执行阶段一的三个测试，3/3 通过；
CI 首次测试步骤因选择表达式语法失败，保留日志，不能记作 CI 通过。追加两项
独立原始数据往返测试后的固定 CI `38516713070` 已执行 5/5 通过，包括原始
逻辑行和带属性的尾部空白。真实像素未测，不能由缓冲测试推定。

第二阶段新增 `apply-lifecycle.py`，仅在独立 checkout 为 Terminal 添加最小
内部接口：保存行、绘制固定 MENU、结束恢复；严格递增代次，过期绘制／关闭
不改当前覆盖。`Terminal::UserResize` 在原生重排前恢复，`Terminal::Write`
在普通输出（包括写回覆盖行、滚动、切换 Alt Screen）进入解析器前恢复。
两项原生 TerminalCore 测试比较覆盖与未覆盖会话；本阶段编译与测试待执行。
调用方必须持有 Terminal 写锁；尚未实现外部 VT 接口、协商、任意菜单载荷、
锁并发测试或 Blueberry 接入，也不声称已生成可安装 Terminal。

还需验证特殊行
宽、图片、链接 custom ID 生命周期、ID 回绕／回收、覆盖区外输出、滚动／截断、
连续缩放代次、桥接断开及渲染器失效通知。原型遇到已回收的链接先拒绝，后续
必须实现原生 ID 保留或完整重映射；不能把拒绝或部分恢复当作满足发布关卡。

只有以上完整性验证及接口集成通过，才可接入 Blueberry。完整历史恢复仍阻塞
发布。本机未发现注册的 Visual Studio C++ 工具链，故使用自有仓库 Windows
Actions 执行原生编译，保存日志与测试工件 90 天。
