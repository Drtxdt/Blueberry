# Windows Terminal 原生覆盖快照可行性原型

固定 Terminal `v1.24.12741.0` / `7ff11ee107c984e236960ec948b450ccbc10187b`。
用户于 2026-10-14 授权独立最小补丁／接口调查。该原型不安装 Terminal，
不修改用户设置，不提交微软仓库 PR，也不作为 Blueberry 发版通过证据。

第一阶段直接使用 Terminal 的 `TextBuffer`、`ROW`、`TextAttribute` 和原生
`Reflow`，不以 CHAR_INFO、UIA 或自行模拟的行模型代替。快照按原始宽度保存
覆盖行，保留原生属性对象、字形、宽字符边界、换行、图像行复制、双字节填充
及滚动标记。恢复必须在持有 Terminal 写锁且 **原生缩放前** 执行。

独立 CI 编译原生测试项目，测试 RGB／默认／索引颜色、独立下划线颜色及样式、
隐藏／保护等属性、中文／emoji／组合字符、URI、连续宽度变化，以及覆盖区域外
新增输入与链接。乱代次和 URI ID 冲突必须在写回前拒绝。

当前状态：原生编译成功，本机 SDK TAEF 明确执行阶段一的三个测试，3/3 通过；
CI 首次测试步骤因选择表达式语法失败，保留日志，不能记作 CI 通过。追加两项
独立原始数据往返测试后的固定 CI `38516713070` 已执行 5/5 通过，包括原始
逻辑行和带属性的尾部空白。真实像素未测，不能由缓冲测试推定。

第二阶段新增 `apply-lifecycle.py`，仅在独立 checkout 为 Terminal 添加最小
内部接口：保存行、绘制固定 MENU、结束恢复；严格递增代次，过期绘制／关闭
不改当前覆盖。`Terminal::UserResize` 在原生重排前恢复，`Terminal::Write`
在普通输出（包括写回覆盖行、滚动、切换 Alt Screen）进入解析器前恢复。
两项原生 TerminalCore 测试比较覆盖与未覆盖会话；CI `38518393691` 已编译并
执行 5 项缓冲测试及 2 项真实入口测试，7/7 通过。首次 Windows 2025 运行缺少
UWP v143 工具集，失败记录保留；成功批次使用 Windows 2022 / VS 2022。
调用方必须持有 Terminal 写锁；尚未实现外部 VT 接口、协商、任意菜单载荷、
锁并发测试或 Blueberry 接入，也不声称已生成可安装 Terminal。

第三阶段 `apply-vt-interface.py` 增加仅实验用途的 OSC 7775 内部接口，用终端
原有解析器处理分片：`draw;generation;firstRow;exclusiveLastRow` 绘制固定 MENU，
`close;generation` 完整恢复，BEL 和 ST 均可终止。行号相对于当前可变视口，
不是用户可直接使用的产品协议。普通 VT 动作在修改缓冲前恢复；私有旧代次
关闭不能移除新的覆盖。新增分片、越界整数、旧关闭、普通滚动及 Alt Screen
原生测试，固定 CI `38520012690` 已执行 5 项缓冲和 4 项 TerminalCore 测试，
9/9 通过。后续 CI `38532075621`（提交 `d2351fb`）已执行 6 项缓冲和 6 项
TerminalCore 测试，12/12 通过，包括物理隐藏列／特殊行宽／图片、原型回复和
滚动后视口坐标。回复明确标为 `prototype;1;nonce;fixed-menu`，不宣称生产支持。
任意菜单载荷、真实 ConPTY 输入通道协商、生产接口安全边界及桥接 EOF 尚未
实现，不把固定 MENU 当作完成 Blueberry 集成。

同一固定 CI 已构建独立便携 GUI，使用 SDK 10.0.22621.0，先生成 Host.Proxy
头文件并构建 OpenConsole。此前缺生成头文件及 SDK 26100 XAML 编译失败的

`probe-runtime.py --output <新文件>` 用于独立、无 profile 的原型终端。它仅发出
带随机 nonce 的能力查询，最多等待 8 秒，取消输入读取并恢复控制台模式，记录
实际回复，不绘制菜单或修改历史。查询往返不能代替完整恢复、像素或最终包
人工验收；不得在正式性能计时中运行。

本机已启动固定 CI 便携副本，在专用设置／无 profile 的查询进程中收到正确

`docs/benchmarks/v0.6/wt-independent-runtime-20261014.json`。没有替换用户安装，
没有修改既有用户设置／profile；真实像素与完整 Blueberry 接入仍未测。

重复成员，解压全新便携布局并创建仅用于探针的设置，启动、记录并清理自己的

## 后续受限菜单接口

用户随后明确接受将独立便携修改版 Terminal 作为正式依赖；这不豁免发布验收。
`apply-menu-frame.py` 增加实验 `frame;generation;top;height;width;utf16hex`，
文本用每个 UTF-16 单元四位十六进制编码。先在独立原生缓冲中完整解析／绘制，
再保存历史并提交；非法载荷不能擦掉当前菜单。只允许可打印 Unicode、行分隔及
现有菜单渲染器的 SGR（复位、粗体和 RGB 前／背景），不执行任意 VT、标题、
剪贴板或光标指令。使用原生字形宽度处理、限制尺寸和载荷，保留覆盖区外字符。
实验 `capabilities;nonce` 回复版本 2 和 `menu-sgr-rgb-utf16hex`；版本 1 查询
仍保留。增加 Unicode／RGB／缩放、非法输入原子性、分片／代次／普通输出回归。
固定 CI `38579522467`（`033f6d3`）已完成原生编译、6 项缓冲与 9 项生命周期
测试，15/15 通过，并生成便携 GUI；真实菜单集成与最终包验收仍未完成。

后续候选增加 `frame;generation;presented/rejected` 输入回复。它确认的是原生缓冲
提交，不能等同于屏幕像素；Blueberry 必须绑定当前编辑行、光标、修订号和候选
身份，不能仅依据已发送数据接受 Tab。跨进程的代次要用系统单调时钟分配，
避免应用重启后从 1 开始被终端当成旧帧。快照改为只保存覆盖行及相关 URI/custom
ID，验证 custom ID 改变时在任何写回前拒绝，不能把拒绝当作成功恢复。重置、
滚动、标记和选择着色等直接 UI 入口先退掉覆盖；连接关闭恢复经调度队列执行，
避免在同步输入回复回调内重入终端写锁。这些后续变更待独立编译、回归及真实
Win32 输入验证，不作发布通过证据。

CI 另以全新便携副本运行流读取及 `ReadConsoleInputW` 诊断，判断默认 Win32
输入模式能否接收查询回复。本机正式计时期间不启动额外 GUI。托管执行器若
没有可用 WinUI 桌面，诊断步骤可以失败，但失败／未执行必须保存在独立工件，
不能由功能 CI 的总体成功填成运行或发布通过。

下一阶段 `apply-native-channel.py` 提供独立确认管道：客户端在自己进程建立
`Blueberry.TerminalOverlay.<随机 GUID>`，Terminal 按服务端 PID 校验后连接。
`native-frame`／`native-close` 绑定该 owner；提交与退场消息只经管道返回，
不注入 PowerShell 按键流。单个工作线程使用事件及重叠 I/O，队列和写入等待
有界，关闭取消并等待线程退出；EOF 经 UI 调度队列恢复，旧 owner 的迟到
关闭不能清除新会话。此变更尚待原生编译和真实便携 GUI 验证，不计作接入完成。

direct 桥接的内部 `BLUEBERRY_NATIVE_OVERLAY=3` 接入只供专用便携配置验证，
还必须握手成功才启用。菜单绑定原有布局及可见帧身份，确认提交后才允许接受；
历史恢复交给原生接口，既有 CHAR_INFO／后台页恢复不会在此路径执行。客户端
的真实本地管道回归已在 CLR 4 和 PS7 CoreCLR 通过，服务端暂由测试替身回复；
这不代表真实 GUI、nested、缩放、性能或最终包验收通过。记录见
`docs/benchmarks/v0.6/native-channel-client-20261015.json`。

原生私有帧另带 `left`，为 nested 保留现有水平菜单位置准备；旧实验版本 2
的零列帧仍保持原格式。`probe-native-menu.cs` 用实际 C# 客户端向独立 GUI
提交两份 Unicode/RGB 菜单并确认退场。它不读取键盘，也不把提交确认当作像素
可见或全部历史属性已验证；托管桌面的失败仍单独保留。

关闭也返回当前代次的 `restored`／`absent` 确认。direct 的按键前退场只有在
终端确认当时确实存在该帧时才保留接受资格；即使退场通知的读取线程延迟，
缩放或滚动已退掉的帧也不能被 Tab 接受。客户端等待有界，未确认时不接受。

桥接接收 EOF 立即关闭独立原生通道，不依赖 UI 刷新。真实桥接接收函数的
断开回归已在 CLR 4／CoreCLR 验证读线程退出；重复清理幂等，Shutdown 即使
End 抛错也会进入清理。实际 GUI 的 EOF 历史恢复仍需与原生服务端一起验收。

旧 Rust 构建缓存已按用户要求删除 12 个中间目录，约 6.47 GiB。历史 ZIP、
EXE、探针、原始测量及 Git 历史保留，清理清单见
`docs/benchmarks/v0.6/build-cache-cleanup-20261014.json`。
