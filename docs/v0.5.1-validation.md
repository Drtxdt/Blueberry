## 功能覆盖

- direct 在私有 PSReadLine 的编辑线程安全点枚举真实 cmdlet、函数、别名；每批最多 64 项，约 2 ms 后让出。会话、快照和偏移校验拒绝旧提示符、乱序和完成后的重放；不完整快照保留旧有效命令。
- 同一个 Shell 的隐藏 NoProfile 辅助进程读取系统模块导出元数据，自动导入仅在该辅助进程关闭。没有执行模块命令或改变用户会话的自动导入选项。辅助进程有超时、退出取消和显式刷新资格检查。
- 系统声明与真实会话定义分别保存；真实定义优先。模块定义不写入持久化 PATH 缓存。
- 首次提示符的 `get`、`GET`、`get-`，三个指定系统命令的菜单和 Tab；profile 函数／别名、705 条别名、删除／重定义、模块导入移除、同名遮蔽、两个并发会话隔离均有自动回归。
- 继续检查原有 Unicode、Vi、重绑定、工作台、迟到帧、Ctrl+C、外部程序返回和签名命令输入协议。

首次候选 `41cc69307156c0f7351298621bee99e78d5699ff` 的 CI `37449805673` 在双会话用例清理时出现 `exit` 变成 `xit`。本地使用原生输入进一步复现了迟到游标回复 `[3;59R` 混入输入。原测试串行驱动两个终端，等待第二个时未及时处理第一个的输出和游标请求。改为独立观察线程持续处理每个终端，并让正常文本使用 Win32 输入记录；不是修改命令文本或跳过失败。修正后连续 20 对并发会话通过，direct 全套再次通过。原始失败与中间实验保留。

游标回复和 F3 的协议歧义可在 [Microsoft 输入状态机](https://github.com/microsoft/terminal/blob/main/src/terminal/parser/InputStateMachineEngine.cpp) 的 `CSI_F3` 分支核对；PSReadLine 将 F3／Shift+F3 映射到字符搜索。迟到回复的本地复现用于解释测试驱动问题，不把所有终端输入异常概括为同一个原因。
