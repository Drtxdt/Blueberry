从成功的目标 `main` push CI 取原包，在该提交仍为 main 时运行 **Qualify frozen main startup** 并提供该次 CI 的 run ID。每种编辑器分别上传八份报告：两个入口 × 冷暖缓存 × 两个批次。将各 `startup.json` 的相对路径按 `startup_entry_reports[profile]["入口/缓存"] = [批次一, 批次二]` 写入版本证据。保留自动 Profile 恢复记录、原始失败、机器身份和工件摘要。六种入口/编辑器组合均须逐批满足 50 ms；热态每组完整菜单 P95 须满足 20 ms。

缩放回归现在同时采集内层 PowerShell 和外层 Blueberry 的原生缓冲区。撤掉尝试性的产品改动后，在 40→95 列的同次失败里，内层第 0 行完整显示提示符及 `gi`，但光标仍在第 1 行第 17 列；外层第 0 行只有提示符，`gi` 出现在第 1 行旧菜单边框中间。两份快照分别为 `shell-28-95.json` 和 `resize-28-95.json`。这把下一处修复定位在重新排版后编辑器光标、旧覆层清除与新输入绘制的顺序上；不能用删除含有输入文本的整行来清理旧边框。

冻结之前仍需核对缩放后当前提示符、历史和编辑行，原包升级生命周期及上述人工项目。正式证据须另外绑定 `terminal_component_sha256`（可安装组件 ZIP 的摘要）和最终 main 的功能及原生终端 CI。草稿附件须与受测字节一致。

本机 PS7/2.4.5 暖缓存、关闭追踪的两对诊断：专用入口相对原生为 +19.13 / +276.23 ms，自动 Profile 为 +496.53 / +533.66 ms。样本太少，不能据此计算正式放行成绩。独立后台服务原型的首个普通入口样本为 +468.29 ms；复用当前 Shell 的入口在暖缓存准备阶段返回 Windows 错误 3，没有生成一对有效样本，不能声称节省了第二次初始化的耗时。原型仅保留在 `experiments/current-profile`，不参与正式产品构建。

已从新生成的核心 ZIP 检查 README 和 RELEASE-NOTES，二者的所有本地链接均指向包内实际文件。最终原包仍须重验。

**本地修复复验。** Nested 普通终端缩放后，适配器从内层控制台核对实际提示符和正在编辑的文本，用 PSReadLine 的 InvokePrompt 重新建立编辑起点。2.0.0 有时把整段输入留在旧行，恢复前先对照实际光标和该行完整文本。外层只在内层确认为空的行上清除与当前编辑行完全匹配的重复画面。55 列提示符经过三次缩放及 Esc、Ctrl+A 后，真实缓冲区为 git st，最终原生屏幕有 status，Unicode 历史及原来的两种 RGB 通过检查。每次通过的测试都保存 git-st-status.json。

**同会话启动复验。** 原版 PSReadLine 在 Profile 前已经加载，隔离脚本现在直接记录缺少编辑器接口的错误。让私有 2.4.5 在 PS7 启动时已加载，两组暖缓存配对中，常规入口相对原生为 +501.07 / +553.76 ms，复用当前 Shell 为 −5.76 / +66.33 ms。在单独的功能测试中，自定义 g 键位处理器在后台服务接入前注册，两次均记录到该处理器实际执行、首键回显及自动菜单。该键位测试有文件写入，其耗时不计入门槛。当前用户安装路径及正式 50 ms 放行成绩仍待验证。

**当前用户模块及退出恢复。** 启用自动 Profile 后，交互式 Shell 使用进程内已有的私有 PSReadLine，后台 blueberry.exe 仅处理补全请求。PS7/2.4.5、PS5.1/2.4.5 和 PS5.1/2.0.0 的独立新进程都核对了启用前、启用后、禁用后的 DLL 路径、摘要及接口。交互回归还实际执行了用户的 g 键处理器，观察首键菜单，核对原 Shell PID、重复加载仅有一个服务会话，并用一次 exit 退出。6e359ac 的本地 ZIP 从公开 v0.5.3 完成升级、回滚、再升级和卸载，新开的 PS7 重新加载原 DLL（SHA-256 为 F8E3A5B7E3E8CAD2130CE10647564A2A0EA15D98DB8A0CC8D589F80154C108E2）。原版已启用的 Profile 在这条升级链中保持原样，测试在升级后重新执行 startup enable 才切换到新模块。

**启动计时。** ddf4502 的本机 PS7 暖缓存 30 对原生对照记录到首键回显增量 P50 为 76.42 ms，30 对均有首键自动菜单。后续版本将启动握手移入随模块安装的桥接 DLL。6e359ac 的首次 30 对复测在第 12 对的原生 Shell 等待提示符超时，该批没有完整成绩。

6e359ac 使用固定 EXE、同一份生成的 Profile 和独立原生终端观察器完成了一批 PS7/2.4.5 暖缓存 30 对。关闭追踪，30 对全部保有自动菜单，配对首键增量 P50 为 +0.1233 ms。该批合格范围仅限这个入口、编辑器和缓存状态。启动完整本地编辑器矩阵后，PS5.1/2.0.0 专用入口的第 9 对已显示候选时，状态诊断仍在写 adapter.tmp，旧观察器立即报缺少 adapter.json 并停止。观察器现在在计时点之后有界等待原子发布，未发布、损坏或降级仍会使验收失败。

在 PR #6 的 PS5.1/2.4.5 第 9 次 OSC 命令快照回归中，child-input.bin 显示宿主先发送 F12,c，再发送光标响应和用户输入 car。shell-wire 中没有这次命令扫描处理器的进入记录，PSReadLine 实际报告 line=ccar、cursor=4。现将首次后台命令快照的私有按键推迟到有编辑输入或显式刷新之后，PATH 索引仍可在提示符出现时启动。回归直接核对编辑缓冲区为 car，再检查 cargo 候选和 700 个别名的最终快照。
