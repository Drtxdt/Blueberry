# v0.5.4 发布验收（未放行）

公开稳定版仍是 v0.5.3。只豁免 v0.5.4 的外部试用，记为未执行；终端、安装与性能没有豁免。

| 项目 | 证据和状态 |
| --- | --- |
| 自动 Profile | PR #5 的原始 AB/BA 工件有 12 组各 30 对，自动入口相对原生的首键增量 P50 为 270.66–319.39 ms，全部超标。 |
| 复用已加载的编辑器 | 在三个受支持组合中，先加载原版 PSReadLine 并设置 F8，再导入私有模块。PS7 拒绝加载同名程序集；PS5.1 虽未报错，活动类型仍来自原版 DLL。三组均保留 F8、均无自动补全所需的编辑器接口。探针为 `scripts/probe-existing-editor.ps1`。没有把这一做法设为默认，也没有取得可发布的同会话启动成绩。 |
| 静态索引 | PS7/2.4.5 的两对同机诊断，顺序为旧/新、新/旧，均为 35 个扫描批次。旧版查询规划 35/36 次，新版 9/10 次；首批至完整候选从 143.07/168.83 ms 变为 78.88/89.82 ms。打开追踪，仅用于判断是否保留合并重算的改动。 |
| 升级 | 在隔离目录用公开 v0.5.3 安装器、核心包和增强包安装，配置用户键位后升级至本地开发包，回滚、再升级、移除组件并卸载。检查配置、Profile 字节、组件状态和用户 PATH。此轮本地开发包非最终冻结包。 |
| 缩放 | 固定 55 列原生提示符，依次缩放到 12×40、28×95、18×60。PS7/pipe 原生屏幕捕获到提示符丢失或重复。试验中从编辑光标推算提示符起始行后，真实缓冲区可以恢复为 `git st`，但原生快照仍捕获到两个提示符，因此未保留这项产品改动。严格回归和快照保留；尚未证明此现象是原 CI 的 Ctrl+A 异常的唯一原因。 |
| GUI 与热态 | 最终包的 Windows Terminal 三组合 direct/nested、VS Code PS7 direct、72 组各至少 300 个样本的热态完整菜单和资源对照仍未验收。 |

从成功的目标 `main` push CI 取原包，在该提交仍为 main 时运行 **Qualify frozen main startup** 并提供该次 CI 的 run ID。每种编辑器分别上传八份报告：两个入口 × 冷暖缓存 × 两个批次。将各 `startup.json` 的相对路径按 `startup_entry_reports[profile]["入口/缓存"] = [批次一, 批次二]` 写入版本证据。保留自动 Profile 恢复记录、原始失败、机器身份和工件摘要。六种入口/编辑器组合均须逐批满足 50 ms；热态每组完整菜单 P95 须满足 20 ms。

冻结之前仍需核对缩放后当前提示符、历史和编辑行，原包升级生命周期及上述人工项目。正式证据须另外绑定 `terminal_component_sha256`（可安装组件 ZIP 的摘要）和最终 main 的功能及原生终端 CI。草稿附件须与受测字节一致。
