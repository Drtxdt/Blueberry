# 0.5 Beta 性能与验收记录

正式数据待本轮冻结后的 release 二进制测量。当前不能宣布启动或热态菜单达到门槛。

## 测量口径

- 首次输入增量：保留用户 profile，交替运行 30 对独立 pwsh 与加载适配器的 pwsh；逐对相减后计算标准中位数。不会用两个总体中位数相减代替配对结果。
- 热态菜单：首词、Git、Cargo、JS、路径、模糊匹配六类场景，每种应用缓存状态分别至少 300 次查询。每个新会话首次查询另记，不进入热态分位数。
- miss 使用新的空数据目录；hit 复用同一份完整命令缓存，并检查命中后缓存文件没有重复写入。OS 文件缓存未清空。
- 输入回显、首个可见菜单、可用目标候选和完整动态结果分别记录。每次计时前必须清除旧输入和菜单；完整动态结果必须有目标候选、可见状态栏，且不带加载标记。无法确认清空或完成时整次运行失败，不跳过慢样本。
- 使用 release、固定配置，正式计时关闭 trace，保留 profile。统计使用偶数样本中间两项均值与 nearest-rank P95，不剔除离群值。
- 工作集和空闲 CPU 只统计 Rust 宿主进程，不包括 pwsh/ConHost/Windows Terminal。输出吞吐使用同一份固定文本和同一 shell 作对照。独立 pwsh 的十次输入回显只用于定位瓶颈，不代替正式热态验收。
- 宿主测量经过外层测试 ConPTY，不能宣称等同于真实 Windows Terminal 的视觉帧延迟。输入法和视觉验收需要另做。
- E 盘本轮已离线，构建与夹具在 C 盘。0.2 的历史数字仅供背景，不能直接宣称为同条件配对加速比。

## 实现取舍

命令枚举在原 runspace 内按 64 项或约 2 ms 分批推进，输入查询优先；完整枚举完成后才移除旧快照缺项。缓存写盘与项目数据查询不在首个输入的同步路径。

启动键位检测使用一次索引后的绑定快照，启动参数通过已验证的环境字段传递，保留原 JSON 协议作为兼容路径。动态结果使用请求号和采集代次，菜单按内容和位置变化更新，并保留所选候选的身份。

named pipe 仍为显式对照路径，默认保持 OSC。管道协议必须通过实际通道检查；回退到 OSC 的样本不能计为 pipe 验收。粘贴载荷在两个通道下均使用会话私有 FIFO 文件，再由 PSReadLine 插入。

预编译 C# 实验未进入运行路径或发布包。保留的 30 对早期实验中，首次输入增益中位数为 -37.88215 ms（桥接方案更慢），没有达到至少降低 20 ms 的保留标准。该实验使用当时的键位配置并包含绑定证明文件 I/O，不能将其数字当作最终版本的精确因果对照。源码与原始数据保留用于复核。

## 正式结果

等待最终 release 冻结后填写。验收标准保持首次输入增量 P50 ≤50 ms、每组热态菜单 P95 ≤20 ms；未达标必须明确列出。
